# Workix

**Мови:** [English](README.md) · [Русский](README.ru.md) · [Español](README.es.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Türkçe](README.tr.md) · [Українська](README.uk.md) · [हिन्दी](README.hi.md) · [中文](README.zh.md)

Workix — це місце, де люди, проєкти й робота знаходять одне одного.

[Хаб Workix](https://workix.co) об’єднує в одному каталозі три складові:

- **Проєкти** — стартапи, продукти та спільноти, які шукають людей.
- **Ролі й замовлення** — відкриті пропозиції роботи з описом, бюджетом, тегами та способом подати заявку.
- **Виконавці** — фахівці, відкриті до нових проєктів.

Workix — не традиційний фриланс-маркетплейс. Він не намагається замінити відносини між проєктом і фахівцем. Оголошення веде до бажаного для власника проєкту способу зв’язку або форми подання заявки, а Workix дає змогу легко опублікувати, знайти й поширити цю можливість.

Люди можуть переглядати каталог у браузері. ШІ-агенти можуть шукати в ньому й керувати оголошеннями через MCP або REST API. Той самий локальний MCP також може збирати пропозиції із зовнішніх платформ, зберігаючи облікові дані платформ на комп’ютері користувача.

**Відкрити Workix:** [workix.co](https://workix.co)  
**Посібник для агентів:** [workix.co/agent](https://workix.co/agent)  
**Довідник API:** [workix.co/api.txt](https://workix.co/api.txt)

## Що міститься в цьому репозиторії?

Цей репозиторій містить відкриті клієнти та інтеграції Workix. Вони використовують API центрального хаба за адресою `https://workix.co`, тому локальна копія може показувати спільний каталог без потреби підтримувати окремий каталог.

- [`views/`](views/) містить сторінки вітрини.
- [`assets/`](assets/) містить браузерний застосунок, стилі, переклади, файли PWA та публічні документи API.
- [`mcp/`](mcp/) містить MCP-сервер на TypeScript, інструменти Workix і адаптери для підтримуваних платформ пошуку роботи.
- [`docker/`](docker/) містить невеликий образ nginx для обслуговування вітрини.
- [`docs/`](docs/) містить публічні посібники для агентів і самостійного розгортання.

Дві основні частини незалежні одна від одної:

1. **Вітрина** — вебінтерфейс для перегляду каталогу Workix. Нею можна користуватися на [workix.co](https://workix.co) або розмістити інтерфейс на власному домені.
2. **MCP-сервер** — інструменти, які дають ШІ-агенту змогу шукати у Workix, керувати вашими оголошеннями та профілем, готувати пропозиції й працювати з підтримуваними зовнішніми джерелами.

Дані каталогу надає центральний API Workix. Для запуску вітрини або підключення MCP-клієнта робочі секрети не потрібні.

## Використання Workix із ШІ-агентом

З `WORKIX_API=https://workix.co` агент може шукати проєкти, ролі, замовлення та виконавців. З `WORKIX_AGENT_KEY` він також може створювати або оновлювати оголошення та керувати профілем виконавця.

Щоб запустити MCP-сервер локально:

Потрібен **Node 22.5 або новіший**: локальне сховище — SQLite через вбудований у Node модуль `node:sqlite`, тому під час встановлення нічого не компілюється.

```bash
git clone https://github.com/facetoplace/Workix.git
cd Workix/mcp
npm install
npm run build
```

Приклад конфігурації MCP для Cursor:

```json
{
  "mcpServers": {
    "workix": {
      "command": "node",
      "args": ["FULL/PATH/TO/Workix/mcp/dist/index.js"],
      "env": {
        "WORKIX_API": "https://workix.co",
        "WORKIX_AGENT_KEY": "wix_…"
      }
    }
  }
}
```

Зареєструйтеся на [workix.co](https://workix.co), щоб отримати ключ агента. Для публічного пошуку ключ необов’язковий, але він потрібен для дій, пов’язаних із вашим обліковим записом.

Облікові дані зовнішніх платформ мають бути лише в локальному середовищі MCP. Не надсилайте до хаба Workix паролі й токени Upwork, Kwork або інших платформ.

Інструкції зі встановлення, перелік доступних інструментів і налаштування окремих джерел наведено в [`mcp/README.md`](mcp/README.md).

## Розміщення вітрини на власному домені

Проєкти та спільноти можуть розміщувати інтерфейс Workix на домені на кшталт `work.example.com`. Дзеркало й надалі отримуватиме дані зі спільного каталогу на `https://workix.co`.

1. Розгорніть `views/` і `assets/` або скористайтеся образом із [`docker/`](docker/).
2. Спрямуйте інтерфейс до хаба:

   ```html
   <meta name="workix-api" content="https://workix.co" />
   ```

   Також можна встановити `API_BASE` або `WORKIX_API` у значення `https://workix.co`.
3. Налаштуйте DNS і хостинг для вибраного домену.

Оголошення, пов’язані з цим доменом, можуть показуватися відвідувачам дзеркала як рекомендовані. Робочий приклад дивіться на [work.facetoplace.app](https://work.facetoplace.app/), а докладнішу інформацію — у [`docs/self-host.md`](docs/self-host.md).

## Використання інших платформ через Workix MCP

Workix MCP також слугує єдиним інтерфейсом для роботи із зовнішніми фриланс-маркетплейсами та сайтами пошуку роботи. Агент може виконувати пошук у кількох джерелах в одному дайджесті, відкривати конкретне оголошення, готувати пропозицію та або надсилати її через доступний API, або складати для вас контрольний список дій у браузері.

Ці інтеграції працюють локально. Токени API, дані для входу на платформи й браузерні сеанси залишаються на вашому комп’ютері та не надсилаються до хаба Workix. Надсилання пропозиції завжди потребує явного підтвердження людиною.

### Готовність платформ

Оцінка показує, наскільки на сьогодні готовий **передбачений робочий процес Workix**, а не ступінь охоплення самої платформи:

- **5/5** — пошук і надсилання заявки працюють через підтримуваний API.
- **4/5** — надійний пошук; для надсилання заявки або автентифікації все ще потрібен резервний спосіб чи діє певне обмеження.
- **3/5** — корисна інтеграція, але облікові дані, проксі або неофіційний інтерфейс впливають на надійність.
- **2/5** — джерело для відстеження за допомогою браузера, а не автоматизована стрічка.
- **1/5** — лише посилання або контрольний список; глибока автоматизація свідомо не передбачена.

Стовпець **Політика автоматизації** навмисно консервативний. Умови платформ і дозволи API можуть змінюватися, тому користувачі також мають дотримуватися чинних правил кожного джерела та власного облікового запису.

2. Підвищити надійність FL.ru, Freelance.ru, Weblancer і Kwork.
3. Додати кращі фільтри для Remote OK та HH.ru і розширити список компаній у кар'єрних дошках роботодавців.
4. Залишити закриті й чутливі до умов використання платформи в режимі роботи за допомогою браузера замість створення ненадійних скрейперів.

### Про джерела з лічильником

Усі джерела вище читаються безкоштовно, крім **JobsPipe**: він списує один кредит за кожну віддану вакансію. Саме тому це єдиний майданчик, якого звичайний дайджест `include_jobs` не торкається — інакше плановий запуск міг би непомітно витратити місячну квоту. Звертайтеся до нього свідомо: інструментом `workix_jobspipe_search`, явним `platforms: ["jobspipe"]` або увімкнувши `JOBSPIPE_IN_DIGEST=1`. Локальний лічильник стежить за витратами цього MCP і не дає почати запит, коли заданий місячний бюджет вичерпано; залишок показує `workix_jobspipe_usage`.

JobsPipe працює лише на читання. Він індексує чужі дошки і не має ендпоїнта для публікації, тому розмістити вакансію через нього не вийде — оголошення потрапить до цього індексу, лише якщо буде опубліковане в джерелі, яке він уже обходить.

### Про міст JobSpy

Indeed, Glassdoor, ZipRecruiter, Naukri і BDjobs читаються через [JobSpy](https://github.com/speedyapply/JobSpy) (MIT), який встановлюєте **ви**: `pip install -U python-jobspy`, Python 3.10–3.12. Нічого не станеться, доки ви прямо не назвете один із цих майданчиків — звичайний дайджест їх не торкається.

Ми викликаємо його, а не копіюємо код, свідомо. Ці дошки читаються приватними ендпоїнтами з обліковими даними з їхніх же мобільних застосунків; так ці дані лишаються у вашій установці, а не поширюються всередині нашого пакета, і автори скрейперів продовжують їх підтримувати.

Врахуйте: у наших тестах результати повернув лише Indeed. Решта блокуються або обмежуються з більшості адрес, а BDjobs зараз падає з помилкою всередині самого JobSpy. Чи запрацюють вони у вас — залежить від вашої мережі, і рішення про їх використання приймаєте ви, дотримуючись умов кожної дошки.
